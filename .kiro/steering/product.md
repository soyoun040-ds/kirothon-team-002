- 목표: 심사 때 **끝까지 동작하는 데모**를 보여 주는 것. 기능 수보다 완성도 우선.

## 주제

- 내 일상에 바로 적용할 수 있는 서비스. 나와 주변 사람이 매일 겪는 작은 불편을 해결하는 서비스.
- 이 제품이 잡은 불편: AI와 함께 과제·팀플을 하며 문제를 해결해도 그 과정이 대화창 속에 흩어져, 지원할 때 다시 정리해야 하는 일.

## 제품: CV 에이전트 (가칭)

개발 과제와 팀 프로젝트를 하는 동안 AI 에이전트와 문제를 해결한 과정을 자동으로 수집해서, 채용 담당자가 읽기 좋은 트러블슈팅 카드(STAR)로 정리하고 이력서·README·자소서로 내보내는 서비스.

## 문제

- 대학생은 AI와 함께 과제와 팀플을 하며 매일 문제를 해결하지만, 그 "어려움 → 해결" 과정은 대화창 속에 흩어져 사라진다.
- 경험이 생기는 시점(학기 중)과 쓰는 시점(지원할 때)이 달라서 과정의 디테일이 가장 먼저 잊힌다.
- 기록을 남겨도 자소서가 요구하는 형태(상황/과제/행동/결과)가 아니라서 다시 정리해야 한다.
- 기존 성과 기록 도구는 직장인 인사평가용이고 GitHub 커밋만 봐서, AI 대화 속 과정은 잡지 못한다.

## 대상 사용자

- 취업 준비를 시작하는 대학교 3~4학년
- 개발 과제, 팀 프로젝트, 공모전을 Kiro 같은 AI 에이전트와 함께 진행하는 학생

## 핵심 기능 (이번 해커톤 범위)

1. **작업 로그 자동 수집**
   - Kiro hook이 프롬프트 입력, 셸 실행 결과(에러 포함), spec 태스크 완료, 에이전트 응답 종료 시점에 셸 명령으로 이벤트를 서버에 전송한다. 이 단계에서는 에러와 해결을 짝짓지 않는다.
   - Git 커밋이 생기면(Kiro 외부 git post-commit hook) diff와 커밋 메시지를 DB에 저장한다.
   - Kiro hook은 "과정", Git 커밋은 "결과의 근거"를 담당한다.
2. **STAR 트러블슈팅 카드 자동 생성**
   - 세션이 닫히면 프롬프트 + 실행 결과 + git diff + 관련 spec 내용을 한 번에 LLM에 보내 트러블슈팅을 찾아 카드로 만든다. (JSON 출력, 세션당 0~3개)
   - 세션 종료 기준:
     1. 기본: spec 태스크 완료(Post Task Execution hook). 태스크 하나가 끝나면 그동안 쌓인 이벤트를 한 세션으로 닫고 카드 생성을 실행한다. 세션에는 해당 태스크의 spec 내용(요구사항, 태스크 설명)을 함께 묶는다.
     2. 보조: 웹 화면의 "지금 정리하기" 버튼. 누르면 현재 열린 세션을 즉시 닫고 카드 생성을 실행한다. 데모에서는 자동 경로(spec 태스크 완료)가 실패했을 때 이 버튼을 쓴다. Kiro의 수동 트리거 hook은 쓰지 않는다.
     3. 선택(시간이 남으면): 20분 무입력. 별도 스케줄러는 만들지 않는다. 새 이벤트가 들어왔을 때, 또는 웹 화면을 열 때 직전 이벤트와 20분 이상 차이가 나면 이전 세션을 닫고 카드를 생성한다.
     - 에이전트 응답 종료(Agent Stop)는 세션 종료가 아니다. 응답 단위 구분용 이벤트로만 저장하고 카드 생성은 하지 않는다.
   - 중복 방지: 세션마다 마지막으로 처리한 이벤트 위치를 저장하고, 카드 생성 시 그 이후 이벤트만 쓴다. 같은 세션이 여러 기준으로 동시에 닫히려 해도 한 번만 처리한다.
   - 근거에 없는 내용, 특히 수치와 결과는 지어내지 않고 "확인 필요"로 표시한다.
   - 오타, import 누락 같은 사소한 수정은 카드로 만들지 않는다.
3. **카드 타임라인**
   - 시간순 카드 목록과 카드 상세 화면. 상세 화면에서 "확인 필요" 칸을 사용자가 직접 채운다.
4. **원클릭 내보내기**
   - 카드를 골라 이력서 한 줄 요약, GitHub README 트러블슈팅 섹션, 자소서 문항 초안(문항과 글자 수 입력)으로 변환하고 복사한다.

## 제품 원칙

- 사용자가 따로 기록하지 않아도 된다. (자동 수집 우선)
- 거짓 이력을 만들지 않는다. 모든 카드는 원본 로그와 diff를 근거로 연결한다.
- 사용자가 최종 확인하고 수정한다. AI는 초안만 만든다.
- 수집 데이터의 API 키, 토큰, .env 내용은 서버로 보내기 전에 마스킹한다.

## 이번 범위에서 제외 (만들지 말 것)

- 로그인, 회원가입, 다중 사용자 (사용자 1명 기준 데모)
- 역량별 필터, 자소서 가치 점수, 채용공고 맞춤 추천
- 노션 스타일의 화려한 보드 (카드 목록 + 상세만)
- Kiro 외 다른 AI 서비스(ChatGPT, Claude 등) 대화 수집

## 성공 기준 (데모)

Kiro로 작은 기능을 만드는 중 에러가 나고 해결하면 → spec 태스크 완료 또는 "지금 정리하기" 버튼으로 세션을 닫은 뒤 웹 화면에 트러블슈팅 카드가 나타나고 → 버튼 한 번으로 README 섹션과 자소서 초안이 생성된다.

### 데모 흐름 (spec 태스크 기준)

1. 이 제품과 별도의 데모용 저장소를 쓴다. 시연은 데모용 저장소에 설치 스크립트로 Kiro hook과 git post-commit hook을 설치하는 장면부터 보여 준다.
2. 데모용 저장소에 spec(요구사항, 설계, 태스크)을 미리 만들어 둔다.
3. 데모용 저장소에 실패하는 테스트를 미리 넣어 둔다. (예: 시간대가 걸린 날짜 처리) 태스크 실행 중 테스트가 실패했다가 수정되어 통과하는 흐름이 생기게 하기 위해서다.
4. 시연에서는 spec 태스크 하나만 실행한다.
5. 태스크가 완료되면 PostTaskExec hook으로 세션이 닫히고 카드가 자동 생성되는 것을 보여 준다.
6. 웹 화면에서 카드를 확인하고, 내보내기로 README 섹션과 자소서 초안을 생성한다.

### 데모를 위한 요구

- 태스크 실행 중에는 사용자 프롬프트가 적을 수 있다. 그래서 셸 실행 결과(테스트 실패와 통과)와 해당 태스크의 spec 내용만으로도 카드를 생성할 수 있어야 한다.

### 대비책

- spec 없이 대화로 작업한 경우는 "지금 정리하기" 버튼으로 세션을 닫는다.
- 시연이 실패할 경우를 대비해, 리허설에서 데모 시나리오를 실제 파이프라인으로 실행해 생성한 카드를 DB에 저장해 두고 백업 영상을 녹화한다. 손으로 만든 카드나 mock-data.ts는 데모 화면에 쓰지 않는다.
